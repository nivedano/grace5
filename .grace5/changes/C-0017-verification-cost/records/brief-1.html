Verification spends work on changed inputs and keeps the required final evidence

Brief for approval. Change C-0017-verification-cost, revision 1, 2026-11-17. Full brief, written by: independent reader.

What you get

  • Execution guidance attributes a run's time to build, packaging, tests and live capture before any reuse is added; a long duration on its own is not treated as waste.
  • Checks run focused while editing, and the complete required set still runs on the clean final candidate.
  • Any reuse documents a cache key covering the relevant source, toolchain, configuration and firmware variants, and the cache is invalidated when any of those inputs changes.
  • A cached artifact never supplies a receipt for different inputs, no required check is skipped, and no receipt is reused across candidates.
  • Hardware is captured live even when build artifacts are reused, and a change to required command semantics returns to the owner gate.
  • The change is guidance only: no new cache service, daemon or kernel command is added, no version, pin, tag or migration row moves, and this change makes no duration-saving claim.

Risks

  • The change is guidance text. No automated check reads it, so only review can confirm that it actually requires profiling, focused iteration and the complete final set; CK1 to CK3 only show that the suite still passes and that the generated packages match the skills.
  • A cache key that omits a relevant input - a toolchain version, a configuration or a firmware variant - would let a stale artifact stand in for changed work, which K2 forbids but no check detects.
  • Reuse is added only after profiling identifies concrete work (K6). If profiling finds nothing, the expected saving does not materialise and the effort spent on the guidance is not recovered.
  • This contract claims no measured saving: duration is evaluated by the control center's adopted method, so the owner approves the guidance without evidence of a benefit, which only later evaluation can supply.

Approval decisions and effort

  • Approve a guidance-only change: no new cache service, command or receipt format is introduced, so the saving depends on execution habit rather than new tooling.
  • Confirm that duration evaluation is delegated to the control center's adopted measurement method (D7) and that this change makes no saving claim of its own.
  • No bench session and no manual procedure is required; all three checks are automated and run without an operator.
