# Notes for C-0006-kernel-managed-paths

Sequence. First commit: package.json 0.5.0, the pin 0.5.0, packages regenerated, so that the iteration runs are not refused on a stale pin. Second commit: the kernel, the tests, the tools and the two ignore files. Third commit: the documents and the regenerated CLI reference. Last commit: the receipts and these notes.

The exclusion lives in one function, `isSource` in `src/git.ts`, read by the candidate, the dirty state and the net diff; the prefixes are `.grace5/` and `<location>/<packaged skill name>/` for the two locations, read once per process from `packages/skills/` through `packagedSkillNames`. The packaged-skill section of `steps.ts` moved to `src/upgrade/skills.ts`, which reads the file system only, so that `git.ts` imports it without a cycle (`steps.ts` imports `git.ts` and `state.ts`); `steps.ts` re-exports it. `PIN_PATH` moved to `pin.ts`, since `git.ts` no longer names the pin. A kernel whose `packages/skills/` is missing cannot define source and fails on the first command that reads the candidate; `refreshSkills` already failed the same way, and the repository is run from its checkout.

The local ignore file is written by `writeLocalIgnore`: created with the two lines where absent, the lines it lacks appended where it exists, left alone where it carries both; the verify of both steps that write it checks the two lines are present. This keeps the 0.1.0 to 0.2.0 step and the 0.4.0 to 0.5.0 step idempotent on a file a person edited by hand. `init` writes it through the same `file()` helper as the pin, so it reports `created:` or `exists:` and never overwrites.

Review-2 F5 of C-0005 is resolved by threading the packaged directory into `Step.verify(root, packaged)`; the runner passes `input.packagedSkills`, and `refreshTheSkills.verify` compares against it. No kernel caller injects one today; the interface no longer allows a mismatch.

Discrimination of the new and amended tests, shown by running the new `upgrade.test.ts` and `helper.ts` against a clone at the start revision bee8a1f (kernel 0.4.0): 7 pass, 11 fail of 18. Fail on the old tree: UP-03 (no 0.4.0 to 0.5.0 step line), UP-04 (no `.grace5/.gitignore`), UP-07 (three steps, not four), UP-09 (`init` writes no local ignore file), UP-12 (the result of the open change does not count after a stale skill is committed, since the old rule hashed the skill in), UP-13 (three steps), UP-14 (the candidate differs from the one the amended rule gives, because the installed skills and `.grace5/README.md` were source), UP-15 and UP-18 (same cause: the helper computes the amended rule). UP-06 and UP-08 fail on the old tree only because the fixture step no longer carries `writes`, which the old runner calls; that is a structural failure, not a behavioural one. Pass on both: UP-01, UP-02, UP-05, UP-10, UP-11, UP-16, UP-17, which this change does not claim. The new verifier does not load against the old tree (`LOCAL_IGNORE_LINES` is not exported there).

The start run's CK6 result (run-1) is a pass of the 0.4.0 verifier on the 0.4.0 tree, as C-0005 recorded for its own start; it is not evidence of what the amended check claims and is not counted at close.
