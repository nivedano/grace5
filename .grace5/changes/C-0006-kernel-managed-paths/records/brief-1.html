Everything the kernel manages leaves the candidate and the diff, so an upgrade and a change are unconnected

Brief for approval. Change C-0006-kernel-managed-paths, revision 1, 2026-11-13. Full brief, written by: independent reader.

What you get

  • Source excludes everything the kernel manages: the whole .grace5/ directory, and the installed grace5-* skill directories under .agents/skills/ and .claude/skills/ whose names are the packaged skill names (today grace5-prepare, grace5-execute, grace5-review). Today only .grace5/changes/** and the pin are excluded. The candidate, the dirty state, the complete diff, the outside listing and the protected-path check all follow, so no write of init, run, close or upgrade changes any change's candidate or appears in its diff. The pilot's "protected path touched" on .agents/** for skill files the upgrade wrote cannot recur.
  • The run-log ignore lines leave the project's .gitignore. The kernel writes a local file .grace5/.gitignore holding "changes/*/records/logs/" and "changes/closed/*/records/logs/", so the logs of open and closed changes are ignored in every initialised repository: init writes it, the 0.1.0 to 0.2.0 step writes it in place of the project's .gitignore, and a new 0.4.0 to 0.5.0 step writes it and nothing else, touching no change. A line an earlier version put into a project's .gitignore is left where it is and documented as removable by hand. The kernel writes no project file any more.
  • With no step able to write source, 0.4.0's source-write refusal, its "writes: <path>" plan line, the --accept-evidence-loss flag and the "evidence of open changes becomes history" line are removed; the flag becomes a usage error. upgrade keeps the refusal, with no override, for a step that would write an open change's directory, and every step still refreshes the installed skills.
  • One more one-time cost at the boundary. Because the rule changes, every repository the kernel initialised, this one included, has one candidate under 0.4.0 and another under 0.5.0 for the same tree, since .grace5/README.md alone makes the difference: results and reviews recorded by 0.4.0 do not count under 0.5.0 and are redone once. Every repository with open changes redoes their final evidence once at this boundary, this one and the pilots alike. source-identity.md and upgrade.md say so, as they do for the 0.3.0 to 0.4.0 boundary.
  • The kernel version becomes 0.5.0, tagged v0.5.0 when this change closes. This repository's own pin is written to 0.5.0 by the change directly.
  • Ledger entries L-23 (the flag and the source-write refusal dropped) and L-09 (the kernel-managed exclusion named) are amended; no entry is added. No command, document or tool is added; one flag goes and one state file, the local ignore file, comes, listed in the method's state row.

Risks

  • The boundary costs every repository its open evidence once more, and the contract says so plainly. The pilot whose lost evidence is this change's Problem loses it one last time when it takes 0.5.0, and this repository redoes the final run and review of this change under 0.5.0.
  • What the kernel does not read, it cannot guard. .grace5/README.md, the local ignore file, the pin and every installed grace5-* skill file can be edited by hand without dirtying the tree, changing a candidate or appearing in a diff; a Protected glob over them, like the pilot's .agents/**, is never reported for those directories. A repository's own directory that happens to bear a packaged name is excluded by name alone (K1).
  • The protected-path rule narrows silently. .grace5/changes/closed/** was already held by review alone; the installed skill directories join it. Nothing in the contract has status say which protected globs it cannot see.
  • Only CK2 reads behaviour, and the same agent writes the tests, the kernel and the CK6 tool. A1 and A2 are each one sentence covering several cases; a missing pairing turns CK2 green without the behaviour.
  • The write boundary is nearly the whole repository: the kernel, the skills, the packages, every method document except the schemas, package.json, README.md, this repository's .gitignore, both state files and the new local ignore file. Five protected paths and the review are the boundary.
  • The work is done in a temporary clone (D4); until the push into the shared repository's master succeeds, the commits and records exist only there. The v0.5.0 tag is made by hand at close; no check shows it exists.
