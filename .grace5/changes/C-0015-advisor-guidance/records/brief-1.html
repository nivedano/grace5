Advisor guidance is packaged, imported once, and checked against current state

Brief for approval. Change C-0015-advisor-guidance, revision 1, 2026-11-17. Full brief, written by: independent reader.

What you get

  • One packaged advisor-guidance resource is the framework's maintained source; a project watchdog imports it instead of carrying a copied second body.
  • An explicit setup action installs or refreshes exactly one OMP-discovered project watchdog import, keeps every byte of existing project guidance, writes no other project file, and changes nothing on a repeated run.
  • grace5-orchestrate and grace5-execute tell the main agent to verify advice against current kernel and git state, resolve contradictions from evidence, drop a superseded observation without a repair narrative, and keep advisor context away from the independent reviewer.
  • A client without OMP gains no runtime dependency, and removing or relocating the resource leaves no silently broken import.

Decisions for review

  • D1The packaged guidance resource is the maintained source; a project watchdog imports it instead of copying a second body.
  • D2The project watchdog import is explicit and project-owned; an ordinary upgrade never creates or rewrites it.
  • D3Existing project guidance is preserved and at most one intended import is added; repeated setup is idempotent.
  • D4The main agent rechecks delayed advice against current state, resolves contradictions from evidence and omits stale repair narration.
  • D5Advisor context is not forwarded to the independent final reviewer, and advice never substitutes for that review.
  • D6advisor.syncBacklog and model or roster changes remain separate measured variables, not hidden in the resource.
  • D7A client without OMP receives no new runtime dependency and no fabricated advisor behaviour.

Risks

  • The setup action writes the project-owned root WATCHDOG.md. Its safety rests on preserving existing bytes, which the contract states but no check reads against a real client repository, so a project that edited the file between runs is protected by the tool's care rather than by an independent observation.
  • Criterion A3 claims the packaged resource is present in the generated distribution, yet its checks are the test suite and the setup help, not package:verify, which is attached to the guidance criterion. The one check that regenerates and compares generated output is not the check named for the distribution claim.
  • The behavioural half of the change — how the main agent treats delayed advice and what it forwards to the reviewer — is judged only by one manual replay. No automated check reads the skill prose, so a wording regression passes CK1 through CK4.
  • CK4, a help listing, is attached to criteria A3 and A5, whose other clauses are about distribution presence and the currency of the generated packages and CLI reference; a help listing establishes little about either, so those clauses rest on CK2 and CK3. CK1's type-check now has its own criterion, A6, which it fits.
