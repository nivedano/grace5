## Migration boundary

Registered step: `0.8.0 -> 0.9.0: refresh the installed skills to 0.9.0 and remove the retired grace5-orchestrate installation`.

The boundary is a step, not a pin bump: the canonical skills changed since `v0.8.0` and `grace5-orchestrate` left the package, so installed `grace5-*` directories must be refreshed and retired installations removed. `apply` does nothing, the runner's refresh carrying the step; `verify` rejects a missing or drifted installed skill file through the same packaged source and, because `skillDifferences` covers retired names, a lingering installed `grace5-orchestrate`; `touches` returns `[]`. No new skill location is created.

The stored-record schemas changed too, by relaxation only: `approval.xsd` makes `brief-sha256` and `brief` optional and `close.xsd` makes `brief` optional, with no newly required element or attribute. Every record written before the release therefore still validates and is read unchanged, so no record transformation is registered.
