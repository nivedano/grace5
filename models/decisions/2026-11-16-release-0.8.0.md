## Migration boundary

Registered step: `0.7.0 -> 0.8.0: refresh the installed skills to 0.8.0`.

The boundary is a step, not a pin bump: the canonical skills changed since `v0.7.0` (prepare, execute, orchestrate and review), so installed `grace5-*` directories must be refreshed. Nothing else in the state moved — the state layout, the local ignore file and the stored-record schemas are unchanged, the schema relaxation needing no transformation because existing records stay valid. `apply` therefore does nothing, the runner's refresh carrying the step; `verify` rejects missing or drifted files inside an installed directory using the same packaged source; `touches` returns `[]`.

The schema relaxation is not a record transformation: `owner`, `recorded-by`, `reviewer` and `by` move from required to optional, so every record written before this release still validates and is read unchanged.

### Test repair inside this act

`bun test --parallel` first failed twice, and the owner ruled that both be repaired inside this act rather than stopping for an ordinary change.

- **UP-21**, the 0.6.0 to 0.7.0 historical-boundary case, looked its step up with `candidate.to === VERSION` and asserted a single-link chain `0.6.0 -> VERSION`. It passed at the 0.7.0 release only because `VERSION` was then `0.7.0`; with the kernel at 0.8.0 the chain from 0.6.0 has two links and the lookup returned `undefined`. It now follows the pattern its sibling UP-19 already uses: the historical boundary is named literally, the plan line is the historical one, and only the pin and the final `upgraded:` line name the running kernel. The historical assertion is retained and strengthened, not weakened.
- **UP-22**, the new case for this boundary, asserted that removing a whole installed skill directory makes `verify` throw. A refresh-only step's `verify` compares the files of directories that exist, so it detects a missing or drifted file inside an installed directory, not an absent directory; the assertion now removes `SKILL.md`. The case also gained the empty-location check, proving the step creates no new skill location.
